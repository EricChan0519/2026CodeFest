# 連鎖店（便利商店、速食、餐廳）資料

導航實驗頁可以直接搜「全家」「麥當勞」「海底撈」「7-11」「kfc」，依離你（或臺北車站）的距離由近到遠列出分店。

## 資料來源

**Overture Maps Foundation — Places**（`theme=places/type=place`）

| 項目 | 內容 |
| --- | --- |
| 費用 | 免費；免帳號、免金鑰，直接讀公開的 S3／Azure |
| 授權 | CDLA-Permissive-2.0（Meta、Microsoft 等）、Apache-2.0（Foursquare）、CC0-1.0（AllThePlaces）；**不含 OpenStreetMap**，沒有 ODbL 的相同方式分享義務 |
| 與本專案 | AGPL-3.0 相容；要標示出處（頁面底部已標示來源、版本、授權） |
| 工具 | DuckDB（MIT）。不是 REST API，而是 GeoParquet；所以我們事先篩出台灣的連鎖店、存成靜態 JSON，使用者搜尋時不會連到任何第三方 |
| 官方文件 | https://docs.overturemaps.org/guides/places/ ・ https://docs.overturemaps.org/attribution/ |

## 為什麼不是別的

| 候選 | 結論 |
| --- | --- |
| Nominatim（OSM） | 免費、開源，但台灣連鎖店不齊（海底撈只回 2 家），一次只回幾筆，不能「找最近的」。保留給地址與地標 |
| Overpass API（OSM） | 免費、開源，可以查連鎖店；但公開伺服器有速率限制、ODbL 要標示並相同方式分享衍生資料庫，而且開發環境連不上。**可當備援**，目前不用 |
| 政府資料開放平臺「全國 5 大超商資料集」 | 免費、政府資料開放授權條款第 1 版；但只有公司登記地址，**沒有經緯度**，也沒有餐廳 |
| 7-ELEVEN、全家的官方店舖地圖 API | 沒有公開的使用條款，屬於官網前端用的介面，不算「開放」，不採用 |
| Foursquare OS Places | Apache-2.0，但現在要註冊取 token、Hugging Face 要審核，不如 Overture 直接 |
| Google Places 等 | 競賽規則禁止 |

## 怎麼更新

```bash
python3 -m venv /tmp/ovenv && /tmp/ovenv/bin/pip install duckdb
/tmp/ovenv/bin/python scripts/build_poi_index.py --release 2026-10-21.0   #
```

輸出 `web/public/lab/poi_index.json`（約 1.7 MB，gzip 後約 0.5 MB；第一次搜尋才下載）。

腳本做的事：

1. 取台灣範圍、`confidence ≥ 0.5`、未標記永久歇業的地點；地址國別必須是 TW（排除金門對岸）。
2. 只用**店名**對照品牌的正規式分類（brand 欄位常被錯掛，例如「阿官火鍋專家」掛成海底撈），並排除「全家福」「海底撈旗魚專賣店」這類同名不同店。
3. 同品牌近距離去重（便利商店 40 m、餐廳咖啡 100 m）；不同來源的同一家店座標常差幾十公尺，英文名與中文名各有一筆。
4. 重複時優先保留中文店名與中文地址。

## 資料品質（誠實揭露）

- 2026-10-21 版共 22,194 筆。和公司公布的店數比，7-ELEVEN、全家、麥當勞約多 10–20%（歇業未下架、不同來源重複、座標位置不同）；**不是官方店鋪清單**。
- 有些地址是英文（來源資料本來就是英文）。
- 頁面底部有標示資料版本與可能歇業；導航只用座標，所以差幾十公尺不會讓人走錯方向，但到了門口附近要看實際招牌。

## 地標、餐廳、學校（後端地點索引）

2026-11-07 回報：「台北市立大學天母體育館」查不到。OSM（Nominatim）在臺北缺很多地點，連「天母體育館」都沒有；Overture 有。
所以把大臺北的 Overture Places 整份（連鎖店除外）做成後端索引，`POST /api/landmarks/search` 查。

| 項目 | 內容 |
| --- | --- |
| 資料 | 同上：Overture Maps Places，2026-10-21.0 版；範圍 lat 24.95–25.22、lon 121.40–121.70（臺北市全部＋相鄰新北） |
| 篩選 | `confidence ≥ 0.6`、營業中、地址國別 TW；店名超過 40 字的不要；連鎖店用 `build_poi_index.py` 的品牌規則排除（前端已有） |
| 大小 | 去重後 157,490 筆；`api/data/place_index.json.gz` 4.3 MB（原始 12 MB），太大不放前端 |
| 隱私 | 使用者位置只用來依距離排序，放 POST body、不記錄（ADR-0005）；搜尋字串不送第三方 |
| 更新 | `/tmp/ovenv/bin/python scripts/build_place_index.py --release 2026-10-21.0` |

比對與排序（`api/app/places.py`）：

1. 名稱包含搜尋字串；搜尋字串像地址（有路、街、段、巷、號）時，地址包含也算（先拿掉「臺北市○○區」、樓層）。
2. 沒有結果：搜尋字串包含整個名稱（「台北市立大學天母體育館」→「天母體育館」）。
3. 還是沒有：字與兩字組大部分相同（打錯字、簡稱）。常見簡稱（北市大、臺大、師大、北科大、北醫、榮總、北車…）會展開。
4. 取最好的那一層，**依離使用者的距離由近到遠**；搜尋字串 4 個字以上時，名稱完全一樣的排最前面（「中正紀念堂」本身排在「中正紀念堂 春水堂」前面）。「體育館」「公園」這種通稱不這樣做。

前端（`web/src/lib/placeSearch.ts`）再和 Nominatim 的路名、地址合併、去重（同名 150 m 內、名稱互相包含 40 m 內），一樣依距離排。

資料品質：少數地點座標不對（例如「新莊體育館游泳池」的地址「公園路11號」被定位到臺北車站旁的公園路），來源本身的問題。

## 外語地點搜尋（韓、日、英、印尼、越、泰、高棉）

2026-11-07 回報：「대만박물관」應該要找到「臺灣博物館」。做法是**先把外語換回中文再搜尋**，結果再換成使用者的語言顯示。
不用 AI 模型（翻譯模型最小也要每個語言方向約 110 MB，專案有大小限制；而且執行階段 AI 必須在裝置端），全部用規則和開放資料，在後端算（`api/app/translate.py`）。

| 資料 | 授權 | 用途 |
| --- | --- | --- |
| Unicode Unihan Database（kMandarin、kHangul、kVietnamese） | Unicode License v3 | 漢字的拼音、韓文漢字音、越南漢越音。只收地點、站牌、連鎖店名稱用到的約 5,200 字 → `api/data/han_readings.json`（166 KB） |
| OpenCC 字典（JPShinjitaiCharacters、STCharacters） | Apache-2.0 | 日文新字體、簡體字 → 繁體（「台湾大学」「士林駅」） |
| 地點詞彙表 `api/data/place_glossary.json`（人工整理，非核心資料） | AGPL-3.0（本專案） | 地點「種類詞」（博物館、公園、車站、醫院、清真寺、就業服務站…）、前綴（國立、市立、捷運）和約定俗成的地名（臺灣、臺北、淡水…），7 種語言 |

更新讀音表：`python scripts/build_han_readings.py --unihan Unihan.zip --opencc-dict node_modules/opencc-js/dist/esm-lib/dict`（Unihan.zip 從 https://www.unicode.org/Public/UCD/latest/ucd/Unihan.zip 下載）。

外語 → 中文（`POST /api/translate/query`）：
1. 依文字判斷語言；拉丁字母再依對到的詞判斷英文或印尼文（Masjid、Pasar Malam → 印尼文）。
2. 由左到右找詞彙表的詞，剩下的是專有名稱。
3. 專有名稱用**讀音**對已知地名（後端 15.7 萬筆地點＋公車站名）：韓文比中文音譯（즈산）和韓文漢字音（지산），越南文比漢越音（Chi Sơn），英文、印尼文比拼音（Zhishan）。對到的字就是中文（芝山）；有好幾個時，常見的在前，畫面給「也可能是…」按鈕。
4. 依中文的順序組回去：前綴＋專有名稱＋種類詞。泰文、高棉文、日文假名沒有可靠的讀音規則，只翻詞彙表裡有的詞；看不懂的部分畫面會標示。

2026-11-07 晚上更新：「每一筆結果都要有使用者語言的內容」。中文 → 外語改成**一定給**（`api/app/localize.py`）：
- 名稱：能完整拆解就整個翻（exact）；拆不完整時，認得的詞翻譯、其他部分用該語言的讀音一段一段寫
  （台北車站雄獅站前門市 → 타이베이역 슝스 역 앞 매장）。一個字的種類詞（山、寺、店、站）只算在名稱最後（龍山寺不會變成「龍 Mountain Temple」）。
  英文、印尼文優先用 TDX 官方英文站名；名稱本身有英文的直接用；連鎖店先把中文品牌換成英文品牌名（星巴克 → Starbucks）。
- 類別：後端地點快照的 65 個中文類別人工對照 7 語（`api/data/place_categories.json`）。
- 地址：拆成 市、區、路／街＋段、巷、弄、號、樓，依語言慣用順序組回（중샤오시루 1단 3호；No. 3, Sec. 1, Zhongxiao West Road）；郵遞區號、里名拿掉。日文看得懂漢字，地址不轉。
- 畫面：使用者語言在上，中文原名、中文地址在下（給路人、司機看）。
- 搜尋：讀音對到的專有名稱多留幾個候選，依「整串中文」在實際地名出現幾次挑（정치대학교 → 政治大學，不是店名常見的「精緻」）；
  英文另外比 TDX 官方英文站名，非拼音的舊拼法也找得到（Chengchi University → 政大）。

（以下為第一版的說明）中文 → 外語（`POST /api/translate/names`）：只有能拆成「前綴＋一個專有名稱（3 字以內）＋種類詞」的名稱才翻（National Taiwan Museum、Museum Nasional Taiwan、국립대만박물관、สถานีรถไฟฟ้า Zhishan）。專有名稱用該語言慣用的寫法（英、印尼、泰、高棉用拼音；韓文用中文音譯；越南文用漢越音；日文用漢字）。拆不出來的（「臺北榮民總醫院」的「榮民總」不是地名）**不硬翻**，只給讀音，畫面同時留中文原名（招牌、站牌都是中文）。公車站在英文、印尼文直接用 TDX 官方英文站名。

限制：詞彙表的韓、泰、高棉、越、印尼文由開發者整理，尚未請母語人士逐條校對；泰文、高棉文寫的專有名稱（例如泰文的「士林」）查不到，要改用英文或拼音。
